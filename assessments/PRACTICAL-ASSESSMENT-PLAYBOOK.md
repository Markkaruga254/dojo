# Practical assessment playbook

This document standardises how to turn course work into evidence without mistaking activity for mastery.

## 1. Before a timed assessment

- Confirm the format, allowed language, library rules, duration, and environment from the actual invitation or platform instructions.
- Practise in a similar editor and runtime; do not assume internet access or package installation will be allowed.
- Prepare a small personal checklist, not a memorised answer.
- Complete at least one full timed rehearsal and record setup friction separately from coding performance.

## 2. During a coding problem

1. Restate the task and constraints.
2. Work one normal example and one edge case by hand.
3. Describe a brute-force approach and its complexity.
4. Find the bottleneck and explain the improved approach.
5. Implement in small steps.
6. Test empty/minimal input, duplicates, boundaries, and a case that would break a naive approach.
7. State time and space complexity and any assumptions.

If stuck, record the point where reasoning stopped. Do not quietly convert a hinted solution into an independent solve.

## 3. After a mock

Within 24 hours, write:
- score and duration;
- problems attempted and outcomes;
- independent / hinted / assisted classification;
- first point of failure for each problem;
- one root cause (knowledge, pattern recognition, implementation, testing, or time management);
- one small remediation task;
- date for a cold re-solve.

## 4. Readiness gate

A gate is passed only when its stated criteria are met and there is evidence. A calendar date, course completion badge, or total number of hours is not evidence of independent performance.

If a gate fails, keep the total workload stable. Replace lower-priority study with a focused 3–5 day remediation loop, then re-test.

## 5. Integrity rules

- Never fabricate assessment dates, scores, test results, user research, or deployment evidence.
- Do not publish real interview questions covered by confidentiality agreements.
- Do not include personal, employer, or user secrets in public notes.
- Use the confidence matrix to identify uncertainty; do not average away a critical role-relevant weakness.
